# 面向大一学生的游戏 AI Agent 汇报：设计规格

## 目标与受众

面向没有人工智能基础的大一学生完成一场约 10 分钟的中文课堂汇报。报告用“设计一名电脑对手”的问题串联游戏设计、传统算法和 AI Agent；不讲公式、不依赖编程经验。学生在结束时应能说清：游戏为什么需要电脑对手、没有 Agent 时如何实现、传统方案的边界，以及 Agent 在何种情况下值得使用。

## 成品形式

- 新建独立 LaTeX 源文件，不改动正在编辑的 `docs/paper/main.tex`。
- 采用 `ctexbeamer`，9 页含封面，每页只承载一个中心结论，适配 16:9 投影。
- 所有示意图使用 TikZ 绘制；不依赖外部图片，保证复制后容易编译。
- 使用虚构的俯视角竞技游戏“脉冲竞技场”作为统一例子：玩家移动、瞄准、射击、躲避。

## 叙事与页面设计

| 页 | 标题 | 中心结论 | 主要视觉 |
|---|---|---|---|
| 1 | 游戏中的电脑对手，为什么需要 AI Agent？ | 主题从“让游戏更有生命力”开始 | 人类玩家与电脑对手对局图 |
| 2 | 一款好玩的对战游戏，想解决什么？ | 有趣、公平、可重复游玩 | 三个设计目标卡片 |
| 3 | 不用 Agent，电脑对手怎样行动？ | 条件规则、状态机、寻路和参数足以做出基础敌人 | 脚本敌人决策流程 |
| 4 | 传统算法：可靠的“规则机器” | 规则方案的工作方式与可控优点 | 有限状态机示意 |
| 5 | 固定规则会遇到什么问题？ | 场景增多、玩家差异和套路识别让规则爆炸 | 规则树膨胀与重复套路图 |
| 6 | AI Agent 是什么？ | Agent 是观察、决策、行动、反馈的闭环 | Agent 闭环图 |

## 写作原则

- 每个陌生词在首次出现时先用日常语言解释，再给出技术名称，例如“状态机：在几个明确状态间切换的规则表”。
- 明确区分“传统算法/脚本”和“AI Agent”：前者按设计师事先写好的规则反应；后者从观察与反馈中选择或调整策略。
- 避免暗示 Agent 天然更强或可替代游戏设计师。强调它也可能不稳定、难测试、成本更高，故常与规则结合。
- 使用具体但不过度承诺的例子；把“学习”表述为训练阶段根据结果改进，而非游戏中随意读取玩家隐私。

## 编译与校验

目标文件为 `docs/student-report/game-ai-agent-intro.tex`。使用 XeLaTeX 或 `latexmk -xelatex` 编译；内容不引用外部图片或网络资源。交付前检查：中文字体、TikZ 图、表格均能排版；标题与段落不会超出投影片边界。

## 范围之外

不讲神经网络结构、强化学习数学推导、代码实现或训练基础设施细节；不将现有技术论文内容直接改写成课堂汇报。
